# Agent Configuration

## Claude

The five universal skill source files (`bro`, `domain-context`, `nix-environment-setup`, `r-dev-shell`, and `visual-verification`) live in `/home/andongni/.nixos-config/dotfiles/universal-skills/` and are exposed through per-skill bridges to all three Claude profiles (standard, `claude-mattpocock`, and `claude-gpt56`), Codex, and OMP's `~/.omp/agent/skills` tree. `lavish` is Codex-authored at `/home/andongni/.nixos-config/dotfiles/codex/skills/lavish/` and is not exposed to Claude or OMP. Home Manager module `home/programs/mutable-configs.nix` wires authored resources through `mkOutOfStoreSymlink`, but dynamic settings are materialized as ordinary writable files.

- Static authored resources are linked individually: `CLAUDE.md`, `statusline.sh`, `commands/`, `output-styles/`, `agents/`, the tracked skill `agent-config-setup`, and the five universal skills `bro`, `domain-context`, `nix-environment-setup`, `r-dev-shell`, and `visual-verification`. The five universal entries under `dotfiles/claude/skills/` are bridges, not source; their canonical source files live in `dotfiles/universal-skills/`. `lavish` has no Claude bridge. The `skills/learned/` directory is runtime-owned and is not linked.
- Dynamic `settings.json` ownership is field-level. The three tracked templates contain only Nix-managed policy; `environment.json` is the shared environment source, and `marketplaces.json` declares profile marketplace/plugin policy. Activation seeds missing files, reconciles only owned JSON leaves atomically, preserves runtime fields, and warns while leaving malformed existing files untouched.
- Claude runtime state remains machine-local: `.claude.json`, credentials, history, projects, sessions, plugin payloads, marketplace caches, and other generated state. Activation bootstraps declared marketplaces/plugins with native Claude commands, enables declared plugins, and removes only the explicitly migrated stale `last30days` declarations from the Matt Pocock and GPT 5.6 profiles.
Theme is launcher-only and is passed per session; do not persist `THEME_MODE` into settings.

## Config directories

Claude has no Codex-style named profiles; each `CLAUDE_CONFIG_DIR` acts like a separate profile directory.

- Default: `/home/andongni/.config/claude` (default `CLAUDE_CONFIG_DIR`).
- `claude-mattpocock`: `/home/andongni/.config/claude-mattpocock`, selected by the `claude-matt` shell alias in `home/programs/shell.nix`, which sets `CLAUDE_CONFIG_DIR="$HOME/.config/claude-mattpocock"` before invoking `claude` (it's an alias, not a separate binary). `cly` / `clty` are `claude` / `claude-matt` with `--dangerously-skip-permissions`.
- `mutable-configs.nix` wires the same `CLAUDE.md`, status line, commands, output styles, and shared effort-tier `agents/` directory into `claude-mattpocock` with `force = true`, but skills are wired per-skill, not as a whole `skills/` directory link: all five universal skills (`bro`, `domain-context`, `nix-environment-setup`, `r-dev-shell`, and `visual-verification`) plus `agent-config-setup` are shared. `lavish` is Codex-only; it is not wired into this profile. Universal source files live in `dotfiles/universal-skills/`; every other skill in that profile now arrives through the Matt Pocock plugin (see below) rather than as mutable files; the former `npx skills@latest` file copies were removed on 2026-07-26.
- `claude-gpt56`: `/home/andongni/.config/claude-gpt56`, launched by the dedicated `claude-gpt56` binary (`clg`; `clgy` skips permission checks). Like `claude-mattpocock`, it wires skills per-skill, not as a whole `skills/` directory link: it shares all five universal skills (`bro`, `domain-context`, `nix-environment-setup`, `r-dev-shell`, and `visual-verification`) plus `agent-config-setup`, while its GPT-specific `CLAUDE.md`, materialized settings, credentials, history, sessions, plugins, and caches remain separate. `lavish` is Codex-only and is not wired here. Do not copy `.claude.json`, `.credentials.json`, histories, sessions, or plugin/cache directories into it.
- **Adding a skill to every Claude profile takes three explicit wirings.** The standard, Matt Pocock, and GPT 5.6 profiles all link skills per-skill. Add the source skill and one `mutable-configs.nix` entry for each profile; these Nix wiring changes require a rebuild. Keep `skills/learned/` runtime-owned.
- **Matt Pocock's skills reach both `claude-gpt56` and `claude-mattpocock` as a Claude Code plugin, not via the shared pool.** Upstream `mattpocock/skills` ships `.claude-plugin/marketplace.json`, so the whole set installs with `claude plugin marketplace add mattpocock/skills` + `claude plugin install mattpocock-skills@mattpocock`. The install itself is machine-local cache; the durable part is the `mattpocock` `extraKnownMarketplaces` entry plus `"mattpocock-skills@mattpocock": true` in `dotfiles/claude-gpt56/settings.json` and `dotfiles/claude-mattpocock/settings.json`. `claude-mattpocock` was migrated off its own mutable `npx skills@latest` file-copy install on 2026-07-26 (37 of its 38 loose skill directories were superseded by the plugin's non-deprecated set). Both profiles remain independent of the Codex-side `dotfiles/agents/skills` pool, which the `npx skills@latest` flow still maintains for Codex and the other non-Claude consumers — that flow deliberately excludes Claude and must keep doing so. Upstream asks for a one-time `/setup-matt-pocock-skills` run per repository.

## Launcher and package

- Launchers: `home/programs/claude.nix` (`writeShellApplication`) — both `claude` and `claude-gpt56` use the Nix-managed Claude Code package and share the same proxy, locale, and `CLAUDE_CODE_*` host environment. The GPT launcher additionally selects its isolated config dir, reads the local client key, starts the local gateway, supplies friendly semantic-slot metadata, and advertises `effort`, `xhigh_effort`, and `max_effort` support through Claude Code's exact `ANTHROPIC_DEFAULT_*_MODEL_SUPPORTED_CAPABILITIES` interface. Gateway model discovery is unset, and `CLAUDE_CODE_SUBAGENT_MODEL` remains unset so Agent calls can select a semantic slot instead of inheriting one global pin. The shared `agents/` directory provides `effort-low`, `effort-medium`, `effort-high`, `effort-xhigh`, and `effort-max`; each definition uses `model: inherit` and fixes its corresponding effort independently.
- Package derivation: `pkgs/claude-code.nix`.
- GPT gateway: `pkgs/cli-proxy-api.nix` packages the pinned no-plugin CLIProxyAPI binary. `home/programs/cli-proxy-api.nix` runs it as a loopback-only user service, renders its secret-bearing config only under `$XDG_RUNTIME_DIR`, stores the local client key under `$XDG_STATE_HOME`, and stores Codex OAuth data under `$XDG_DATA_HOME`. Run `cli-proxy-api-codex-login` once to authorize Codex. The gateway retains exactly three base aliases: `claude-gpt-5-6-sol`, `claude-gpt-5-6-terra`, and `claude-gpt-5-6-luna`. `dotfiles/claude-gpt56/settings.json` restricts `availableModels` to `opus`, `sonnet`, and `haiku`, defaults to `opus` with high effort, and uses `modelOverrides` to map the current Claude Code canonical IDs (`claude-opus-4-8`, `claude-sonnet-5`, and `claude-haiku-4-5-20251001`) to those gateway aliases. The canonical IDs are version-specific: after a Claude Code upgrade, verify all three direct semantic routes and built-in Agent model overrides against live `modelUsage`, then update the keys if necessary. Model and effort are independent; Claude Code's native session effort is translated upstream without alias-specific `reasoning.effort` overrides.

## Workflow

1. Locate the tracked source under `dotfiles/claude/` (Claude-only resources), `dotfiles/codex/` (seven Codex-authored skills, including `lavish`), `dotfiles/universal-skills/` (the five universal skills), or `dotfiles/agents/skills` (the separate Codex shared pool) first; edit there, never a runtime copy under `$CLAUDE_CONFIG_DIR` or `~/.codex`.
2. Keep edits scoped to the requested change.
3. Commit the change so the repo's pre-commit hooks are the verification gate (repo policy) — do this even for changes that are already live via symlink.
4. Rebuild with `sudo nixos-rebuild switch --flake .#system --impure` (or the `rebuild` alias, which targets `/etc/nixos#system` and works from any directory) only when the change touches a materialized file (`settings.json`) or Nix wiring itself (`mutable-configs.nix`, `theming.nix`, `claude.nix`, `cli-proxy-api.nix`, `codex-desktop.nix`, or a package derivation). Pure content edits to already-wired symlinked files (`CLAUDE.md`, `skills/`, `dotfiles/universal-skills/`, `commands/`, `output-styles/`, `agents/`, `statusline.sh`, `AGENTS.md`, `rules/`, `dotfiles/agents/skills/`, `dotfiles/codex/profiles/`) are already live — commit only, no rebuild required.
