# Work on Home Device

1. Verify both ends before acting. Record the current hostname, Git checkout, and `/etc/nixos/local.nix` role; then use `ssh home` to confirm that the target hostname is `linglong` and `portable.role` is `"home"`. Treat the source and home hosts separately: role-gated home behavior belongs only on `linglong`, and the other host may have `portable.role = "remote"`.
2. Inspect Git state on both hosts before changing or transferring anything. Preserve dirty and untracked files, compare HEAD, branch, upstream, and `origin`, and never reset, clean, overwrite, or silently include unrelated work. Both checkouts must retain the canonical origin `git@github.com:lyh970817/nixos-configuration.git`.
3. Transfer committed history with normal Git when possible. If the home host cannot SSH back to the source, create a Git bundle in a source-side path returned by `mktemp`, create a distinct home-side path with `ssh home mktemp`, copy the bundle there, verify it, and fetch or fast-forward without changing `origin`. Validate each generated path before use, install cleanup traps where practical, and remove only those exact paths on both hosts; never use a fixed temporary filename, glob, or broad temporary-directory cleanup.
4. Keep edits role-aware. Change shared modules only when behavior is genuinely shared; gate home-only packages, services, hardware, desktop behavior, and secrets on `portable.role == "home"`. Do not make the remote role emulate the home role merely to simplify a transfer.
5. Copy secrets only through an explicit allowlist: `secrets/coding-cli/`, `secrets/mihomo-cache/`, and `secrets/hyprwhspr-credentials.json`. Keep credential directories mode `0700` and credential files mode `0600`, preserve ownership, compare without printing secret contents, and never stage or commit copied secrets. Never recursively mirror `secrets/`, use a deleting sync, or copy `secrets/mihomo-config.yaml` between hosts.
6. Commit each scoped configuration change before rebuilding so pre-commit hooks provide the verification gate. Preserve unrelated work, synchronize the resulting committed history between the source and home checkouts, then rebuild both machines: rebuild the source machine locally and rebuild home interactively with `ssh -t home 'sudo nixos-rebuild switch --flake /etc/nixos#system --impure'`. This synchronization and two-host rebuild are always required before reporting completion, including for role-gated changes. If either rebuild fails, make a follow-up fix commit before rebuilding both machines again.
7. Treat any edit to the live host's `secrets/mihomo-config.yaml` as connectivity-critical. First bootstrap a known-good baseline with `sudo mihomo-guard keep`. Apply an edit only with `sudo mihomo-guard try` (or `sudo mihomo-guard try 120` for an explicit timeout), which briefly restarts all TUN traffic and arms the default 90-second auto-revert. If connectivity remains good, immediately run `sudo mihomo-guard keep`; if the edit is bad but the session survives, run `sudo mihomo-guard revert`; if connectivity is lost, do nothing and let the timer restore the last-good file and restart mihomo. A reboot while pending also restores last-good before mihomo starts. Inspect `mihomo-guard status` as needed; rejected content is preserved at `/var/lib/mihomo-config/rejected.yaml`.
8. Report the source host and home host separately. For each, state hostname and role, Git HEAD/branch/upstream/dirty state, transferred mutable state, rebuild result, relevant service failures, and any intentionally preserved differences or untracked files.
