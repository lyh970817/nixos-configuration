- [ ] Add `screen-verify type` and `screen-verify click`, gated on session ownership in code rather than prose. Both must refuse to inject into any window whose address is not session-owned and on the stage; driving an unowned window should require an explicit flag, matching how `--no-stage` already works for capture.   Motivation is interaction *in service of* verification, not general computer use: states reachable only after input — a query typed into `rofi`, hover and focus rings, an open dropdown, a dialog's error state — are pixel-verifiable only and currently unreachable, since `screen-verify` can launch and photograph a test surface but cannot drive it. - [ ] Decide whether the Stop-hook rewriter should carry two contracts instead of one, and only then whether it can pick between them reliably enough to be worth it.

  The second contract would be a deliberation shape for brainstorming and design turns, alongside the existing status/digest shape for turns reporting work. Roughly: the question being decided → the options with their costs → the recommendation and why → what is still open → `Watch out`. This is not invented; it is `AGENTS.md` §9's own escalation form in FirstMate ("Lead directly with concrete evidence, then the consequence, options when applicable, and a recommendation"), which sits beside the four-section `/bearings` status contract rather than replacing it. FirstMate's whole pattern is a small set of named contracts with one selected per situation, so a second contract is the natural next step — see [`docs/firstmate-reporting-architecture.md`](docs/firstmate-reporting-architecture.md) for that architecture, what was taken from it, and the measurements behind the current single-contract prompt.

  Selection is the crux, not the second shape. A design discussion rendered as a status report is worse than no rewrite at all: it fabricates a settledness the turn did not have, and the reader loses the actual reasoning. The current prompt therefore deliberately offers the model **no** format branch — that judgement was what the previous model tier handled worst. Sonnet 5 is stronger, but that must be measured, not assumed.

  Classification accuracy is the top-line metric, above retention. Hand-label the corpus as status / discussion / mixed, run the prompt, and report the confusion matrix. Mixed messages will be common and need an explicit tie-breaker written into the prompt, not left to the model. If selection proves unreliable, fall back to a single contract and close this out — a reliable one-shape rewrite beats an unreliable two-shape one.

- [ ] Two Hyprland Lua-IPC translations are silent no-ops and may bite again elsewhere. Recorded because the API gives no signal at all for either.

  `hl.dsp.workspace.move({ workspace = "name:X", monitor = "OUT" })` and `hl.get_monitor("OUT"):set_workspace({ workspace = "name:X" })` both answer `ok` and change nothing when the output has merely switched *away* from a workspace it still owns. The legacy `moveworkspacetomonitor` re-homed a workspace *and* made it active; the Lua call only re-homes it. What works is focusing the output and then the workspace -- `hl.dsp.focus({ monitor = … })` then `hl.dsp.focus({ workspace = "name:X" })` -- which `screen-verify`'s `ensure_stage_workspace` now does, restoring focus afterwards so the keyboard never stays on the stage.

  The general rule this is an instance of, and the reason to keep it written down: **unknown dispatcher *fields* are silently ignored while unknown *values* are rejected**, so a wrong field name is indistinguishable from success. `Hyprland --verify-config` cannot see it either -- it validates key strings and config keys, not dispatcher fields. Verify the observable *effect* of any new `hl.dsp.*` call against a live compositor; `ok` proves nothing. This already nearly shipped `cycle_next({ prev = true })` (the field is `next = false`) cycling windows forwards forever.

  Reference material, better than guessing: the wiki's Dispatchers page is the argument-name authority (`gh api repos/hyprwm/hyprland-wiki/contents/content/Configuring/Basics/Dispatchers.md`), because `share/hypr/stubs/hl.meta.lua` in the `hyprland` package types every dispatcher as `fun(...)`.
