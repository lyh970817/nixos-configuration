- [ ] Add `screen-verify type` and `screen-verify click`, gated on session ownership in code rather than prose. Both must refuse to inject into any window whose address is not session-owned and on the stage; driving an unowned window should require an explicit flag, matching how `--no-stage` already works for capture. The enforcement hook exists today: `screen_verify.py` tracks `pid` and `window.address` per owned process and has `owned_stage_addresses()`. Bare `ydotool` has no concept of a target window and types wherever focus happens to be, which is exactly why this belongs behind `screen-verify` instead of a loose instruction to call `ydotool`.

  Motivation is interaction *in service of* verification, not general computer use: states reachable only after input — a query typed into `rofi`, hover and focus rings, an open dropdown, a dialog's error state — are pixel-verifiable only and currently unreachable, since `screen-verify` can launch and photograph a test surface but cannot drive it. Keep this inside `visual-verification`'s existing restrictive gate; do not generalize that skill into a computer-use skill, whose enabling framing would erode the gate that stops screenshot-spam. Note that input is not reversible the way `preview` snapshot/restore and `end` cleanup are, so ownership confinement is the substitute for restorability. Build it when a real task stalls on it, not speculatively.
